# 数据要变成世界

> 发布日期:2026-08-18 · [中文](../zh/2026-08-18-数据要变成世界.md) | [English](../en/2026-08-18-data-has-to-become-a-world.md)

---

很长时间里，我们一聊训练智能，最容易想到的词就是数据。

更多数据，更干净的数据，更好的标注，更大的语料，更多正确答案，更多错误案例，更多人类反馈，更多专家示范，更多高手留下来的操作轨迹。

这些当然都重要。

但它们正在变得不够。

下一步真正值得问的问题，不只是「我们有什么数据」。

更重要的问题是：「这个系统能在哪个世界里练习？」

一句话可以教会模型人怎么说话。一篇文章可以教会模型人怎么表达。一段操作记录可以教会模型一个任务表面上长什么样。可一个要真正做事的 Agent，不能只活在文本里。它需要一个地方，在那里行动会产生后果，错误不是被描述出来的，而是被它亲自撞上的；反馈不是写在答案后面的评语，而是在一次决策之后真的回来；同一个局面可以重置、回放、变化，然后再测一次。

到了这一层，数据就不再是一堆静态样本。

数据要变成一个可以运行的实验。

## 样本不够，世界才够

静态样本当然有用。它告诉我们：这是一个好答案，这是一个坏答案，这是以前有人怎么做的。

问题在于，真实工作很少以干净样本的形式出现。

真实工作总是带着状态来的。事情已经发生了一半，某个文件已经改过，某个承诺已经说出口，前一次决策已经制造了约束，一个工具调用会改变下一步能不能走，一点小错也不会停在原地，而是会把后面的分支全部带歪。

所以很多 AI Demo 看起来很惊艳，到了真实生产环境里却很脆。

Demo 展示的是输出。

生产环境测试的是行为。

一个输出，可以被判断一次。

一个行为，要穿过一整段连续过程。

如果 Agent 只是写一封邮件，你读一遍就能判断大概好不好。可如果 Agent 要管理一整段工作流，问题就变了：它有没有发现缺失信息？有没有在正确时机提问？有没有避开不该碰的文件？有没有保留上一次决策？工具失败后会不会恢复？该停的时候知不知道停？有没有给下一次运行留下证据？

这些不只是写作问题，也不只是模型问题。

这是环境问题。

Agent 需要任务、工具、记忆、权限、初始状态、变化中的状态、外部事件、失败模式，以及一个能判断成败的验证器。没有这些东西，我们测试的就不是「会不会做事」，而是「会不会说得像在做事」。

这个区别很容易被忽略，因为语言太会骗人了。一个流畅答案会制造能力感，一个结构完整的计划会制造进展感。

但工作不是进展感。

工作是世界反推之后仍然留下来的东西。

所以，世界必须进入训练循环。

## 强化学习早就知道这件事

这个想法并不新。强化学习从一开始讲的就是交互。

在强化学习的经典表述里，这个领域研究的是一个学习中的 agent 如何与环境交互，以实现某个目标。[^1] 它不是只吸收样本，而是行动，观察变化，获得反馈，然后调整自己。

这个结构非常简单：

Agent，环境，行动，反馈。

听起来基础，但基础不等于浅。

AlphaGo Zero 把这件事展示得很戏剧化。2017 年 Nature 论文介绍的算法，只依靠强化学习，不使用人类棋谱数据，也不使用除围棋规则之外的人类领域知识。[^2] DeepMind 当时披露，经过 3 天自我对弈训练，AlphaGo Zero 以 100:0 击败此前公开版本的 AlphaGo；经过 40 天训练后，它超过了之前所有版本。[^3]

当然，关键教训不是「自我对弈解决一切」。围棋是一个规则清晰、边界封闭、胜负明确的世界，而绝大多数真实工作不是这样。

真正的教训更精确：

当一个世界被定义得足够好，经验就可以被制造出来。

这才是厉害的地方。系统不必被动等人类生产样本，它可以自己尝试，观察结果，对比差异，然后改进。

但这一切成立的前提，是环境足够强，能回答它。

棋盘会执行规则，游戏会结束，胜负可见，同一个开局可以回放，变化可以探索，进步可以测量。

没有这样的世界，「自我改进」很容易变成表演。

系统生成一个答案，再评价自己的答案，再修改答案，看起来更聪明了。可如果裁判和选手有同样的盲区，这个循环可能只是把错误打磨得更漂亮；如果任务没有真实后果，系统学到的可能是「改进的语气」，不是改进本身；如果评测空间直接暴露给系统，它学到的可能是通过考试，而不是做好工作。

所以，难点不只是造 Agent。

难点是造一个能教会 Agent 的世界。

## 好环境贵在正确的地方

一个严肃的环境，至少有三样东西。

第一，任务。

不是「帮我研究得更好一点」「让客户更满意一点」这种模糊愿望，而是有目标、有约束、有输入、有可用工具、有禁止动作、有完成定义的任务。任务越清楚，经验越有用。

第二，状态。

真实环境会记住事情。它有文件、账号、消息、日程、上一轮尝试、局部失败和副作用。Agent 必须学会：行动会改变世界。这正是任务活起来的地方。

第三，验证器。

必须有某个人或某个机制判断工作到底有没有成功。有些验证可以自动完成，比如测试通过、答案匹配、交易完成。有些验证必须有人参与，比如语气、品味、风险、实用性和时机。但无论如何，都要有一条独立于 Agent 自信心之外的判断通道。

很多团队低估的，恰恰是这里。

他们以为产品是 Agent。

很多时候，真正的产品是 Agent 周围的环境。

任务失败后能不能重置？同一个局面能不能用不同模型回放？环境能不能扩展，同时又不泄露答案？能不能加入真实噪音？能不能保留决策轨迹？能不能把研究空间和评测空间隔离开，避免系统只是优化分数？能不能把一个混乱的真实流程变成可重复训练的场地，同时又不假装它很干净？

这些问题不华丽。

但它们决定学习能不能复利。

在旧的数据世界里，最值钱的资产可能是一大堆样本。到了 Agent 世界里，最值钱的资产可能是一套活环境，它能持续生产有意义的经验。

新的数据集，不再是一张表。

它是一座小世界，有规则，有记忆，有阻力，也有后果。

## 人也是这么学会的

这个模式也适用于人。

我们大多数人收集了太多关于自己的静态数据。

收藏金句，保存笔记，划重点，写计划，列原则，听别人讲方法。资料库越长，我们越容易觉得自己在进步。

但资料库还不是学习环境。

一条笔记如果从不改变你的行动，它大多只是装饰。一条原则如果从不在压力下被测试，它大多只是自我形象。一份计划如果从不遇到约束，它大多只是带项目符号的幻想。

人要真正学习，也需要一个世界。

公开写作就是一个世界。你发出去，读者回应你或者忽略你，软弱的论证会暴露出来，下一篇文章就继承这次教训。

每周复盘也是一个世界。你先做预测，再行动，再把结果和预期放在一起看，然后更新规则。

一门小生意更是一个世界。客户会付钱或拒绝，流程会断，承诺会撞上产能，模糊想法会变成真实成本。

个人 AI 工作流也可以是一个世界，但前提是它有任务、有状态、有验证器。否则，它只是一本更会夸你的笔记本。

所以，「用 AI 更快学习」这句话经常被误解。

更快的总结，不等于更快的学习。

总结给你压缩后的信息，学习需要你接触后果。

问题不是 AI 有没有解释清楚概念。

问题是你有没有搭出一个场景，让这个概念必须真的管用。

## 未来属于造世界的人

模型越强，表层工作越便宜。

生成计划会更便宜，写答案会更便宜，做原型会更便宜，翻译文档会更便宜，甚至制造样例也会更便宜。

真正变贵的，是构造一个能检验这些输出的情境。

这是一门新的手艺。

它要求你把任务定义清楚，保留足够上下文，引入真实难度，保护评测空间，捕获失败，并把反馈带进下一次运行。它要求你重视那些不性感的东西：权限、重置、日志、rubric、边界案例、反例、回滚、复核和记忆。

这听起来像工程。

它确实是工程。

但它也是一种成长哲学。

人不是因为听了更多正确的话就变强的。人是在自己的行动进入一个能教自己的循环之后，才开始变强的。

你尝试，现实回应，你检查差距，你调整系统，下一次尝试就比上一次多带了一点真实。

AI 会让这个循环变得更明显，因为机器会逼我们定义过去一直含糊的东西：

任务是什么？

环境是什么？

什么算成功？

什么必须记住？

什么必须忘掉？

什么可以改变？

什么必须和学习者隔离？

这些不只是 AI 问题。

它们是披着技术外衣的人类问题。

只收集数据的人，会拥有越来越大的资料库。

会造世界的人，会持续生产经验。

而经验一旦可以被重置、回放、挑战和判断，就不再只是信息。

它会变成一种进化方式。
