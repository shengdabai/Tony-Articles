# 什么时候该让 AI 打断你

> 发布日期:2026-09-30 · [中文](../zh/2026-09-30-什么时候该让%20AI%20打断你.md) | [English](../en/2026-09-30-when-should-ai-interrupt-you.md)

---

设想你正读一篇英文文章，指针停在一个生词上。释义立刻弹出，你接着往下读，几乎没有被打断。第二天，那个词又出现了，你还是不认识。工具完成了查词这件事，却没帮你形成下次认出它的能力。如果它在你继续阅读前多问一句，让你先猜词义，会不会更好？答案取决于你此刻究竟想赶完文章，还是想学会这个词。

一份关于个人 AI Agent 的链接摘要把理想体验描述成后台做事、偶尔报告结果，甚至让人感觉不到它的存在。这里的 Agent，指得到目标和边界后，能自己安排步骤的软件助手。另一份录音整理提出了相邻的问题：查到词和记住词是两件事。这些都是二手整理，不是我亲历的产品测试，也不足以证明哪种交互一定有效。但它们让我想追问：当 AI 越来越会主动帮忙，我们该把哪些打断看成多余，哪些打断看成学习所需的机会？

我的判断是：个人 Agent 的好坏，不能只看它替你消除了多少步骤，还要看它有没有识别出值得交还给你的判断。重复、低风险的动作，可以安静地做；遇到你正在学习、以后还需要独立完成的判断，适时停一下可能更有价值。关键不是让机器多说话，而是让一次打断换来一次真正的练习。

## 一味安静，会把什么一起收走

想象一个 Agent 帮你处理每天都要看的资料。它会筛选、归类、提炼结论，最后送上一段简洁的摘要。你节省了时间，也可能失去接触原始材料中矛盾、缺口和例外的机会。如果你的目标只是知道今天有没有需要回应的事项，这种省略很好；如果你的目标是学会判断一份资料靠不靠谱，省略的恰好可能是练习本身。

这不是说费劲就必然有收获。把一堆杂乱页面手动复制到表格里，通常不会让人更会分析。我要保留的是那种能改变下一次选择的用力：先猜结论，再核对证据；先指出哪里可能错，再看机器怎样解释。真正值得交还给人的，往往是问题尚未被整理整齐的那一小段。

[Shen 与 Tamkin 在 2026 年的一项随机实验](https://www.anthropic.com/research/AI-assistance-coding-skills)里，让 52 名有 Python 使用经验、但没接触过目标程序库的开发者学习新工具。使用 AI 的一组在紧接任务的测验中平均得分为 50%，手写代码的一组为 67%；使用 AI 的一组完成任务略快，但实验还不能排除这种速度差只是偶然波动。最值得我留意的是，两组差距在排查代码错误的题目上尤其明显：一个人可以拿到能运行的结果，却不一定能解释它为什么在别处出错。

这个实验规模小，只测了一种程序库和任务后的即时理解，不能推出长期能力必然下降，更不能直接推出所有个人 Agent 都会伤害学习。研究者在录像里还观察到，向 AI 追问概念、核对自己理解的人，表现通常好于主要让 AI 生成代码的人，也好于主要依赖 AI 排错的人；后两种是分别观察到的使用方式，不是同一群人同时交出两项任务。这部分是行为关联，不能当作追问必然带来高分的因果证明。它给我的提醒很具体：同样叫作“使用 AI”，人在过程中做了什么，差别很大。

另一个角度来自 [Lee 等人在 2025 年发表的知识工作调查](https://www.microsoft.com/en-us/research/wp-content/uploads/2025/01/lee_2025_ai_critical_thinking_survey.pdf)。319 名受访者提供了 936 个工作中使用生成式 AI 的例子；他们对 AI 完成某项任务越有信心，就越少回答自己在该任务中进行了批判性思考，也就是核对依据、检查结论能否站得住。这里问的是有没有这样思考，不是思考了多少。受访者也描述了思考位置的移动：自己动手产出的部分变少，核实信息、整合回答和照看任务目标的工作变多。这是自报调查里的相关性，无法证明 AI 使任何人的思考能力退化，却说明“省下动作”之后，审查能力可能更需要被练出来。

我把这看作一种容易漏算的成本。只统计 Agent 替我读了多少页、写了多少字、点了多少按钮，很容易高估进步。假如下一次资料换了结构、结论与原文相反，我能不能发现？如果不能，之前的顺畅至少还没有转化成我自己的判断。这不是要求每次都从头做，而是提醒自己：有些步骤消失时，相应的练习也一起消失了。

## 什么时候打断才值那一下

打断有成本。正在写东西的人被提醒一次，可能要花一段时间才能回到原来的思路；忙着完成任务的人，也未必愿意当场上一堂课。因此，不能把“让人学习”当成 Agent 随时插话的理由。先问清楚它要争取的是什么：防止眼前做错、帮人形成下次能用的判断，还是仅仅让界面显得很积极？第三种不值得打断。

拿开头的生词来说，第一次看到时，快速给出释义也许最合适。若读者主动选择“我想记住”，工具可以在合适的停顿处遮住答案，让人先猜，再给解释。这里的干预不应被包装成查词的默认义务：读一份急需看完的材料，和专门练词汇，本来就是两种任务。先确认人的目标，才谈提醒的时机。

我会用三个问题决定是否让 Agent 开口。这个判断以后还会出现吗？人目前是否有足够线索尝试，还是必须先得到基础信息？这次尝试之后，能否很快收到清楚的反馈？如果三项都成立，短暂停顿可能值得；若答案完全无从猜起，硬让人猜只是在制造挫败。若任务一次性完成、结果容易核验，也没有学习目标，安静代劳更合理。

关于反馈频率，[Bosse 等人的 2015 年实验](https://link.springer.com/article/10.1186/s12909-015-0286-5)提供了一个有限的参照。47 名医学生在模型上反复练习置入鼻胃管，也就是从鼻子通到胃里的管子；专家反馈指针对刚才的操作指出哪里做得好、哪里需要调整。两组都在尝试后收到反馈，只是次数不同。两组练习后的表现都改善；反馈更频繁的一组在最终的整体操作流畅度评分上更好，但分步骤的评分差异没有达到同样明确的结论。研究只测了模拟操作的早期表现，也没有比较尝试前与尝试后给反馈。它提醒我留意反馈改善的是哪一种表现，却不能证明 AI 该在何时打断。

我由此提出一个尚待检验的设计猜想：如果 Agent 在你还没作出判断前就揭晓答案，它提供的是替代；若它等你做出一个可检验的猜测，再指出具体偏差，这次提示才可能成为反馈。两者在屏幕上可能只差一次点击，在学习上却不是同一件事。类比做菜：自动灶具替你维持温度，让晚饭更快上桌；若你想学会看火候，偶尔自己判断何时调火，再对照结果，会更接近练习。做菜有气味、触感和即时后果，读资料或用 AI 的判断常没有这么直接的信号，所以类比只说明“先判断、再反馈”的顺序，不证明某种交互一定有效。

## 把提醒变成练习，而不是新通知

我们已经被太多通知训练成了“看见就划掉”。如果 Agent 每完成一步都报喜，每发现一个小问题都叫人看，它迟早会和弹窗广告一样被关掉。我想要的打断应当很短，并且与刚才的任务紧挨着：指出一个分歧，请我在两个有理由的选项之间作判断，再展示为什么。报告“我发现一个问题”还不够；它应该让我看见我原先依据哪条线索作出了选择。

设想你正在用 AI 整理一段公开研究。摘要写得流畅，Agent 发现原文只测了短期表现，而你的文字却写成长期效果。它可以直接改掉这句话，也可以先把冲突标出来，问你该把结论收窄到哪一层。若你正在赶一个已有明确核稿人的交付，直接标注待核实处可能更合适；若你正在练习读研究，自己先试着改，再看依据，才有机会学会“样本与时间范围不能凭感觉外推”这个判断。提醒的内容相似，用途却不同。

练习还需要换一道题。[Schorn 与 Knowlton 在 2021 年的实验](https://link.springer.com/article/10.3758/s13421-021-01168-z)让参与者练习几种按键序列：固定练习是先重复一种再换下一种，交错练习是把几种穿插着练；第二天分别测旧序列或相似新序列。固定练习在当下进步更快。测旧序列时，交错练习过的人在两种测试顺序下都能保持表现，固定练习过的人遇到交错测试则表现变差。测新序列时，交错练习组在两种测试顺序下都有进步，固定练习组只有在新序列仍按固定顺序呈现时才有进步；但总体上两种训练方式的差异并没有达到明确结论。实验测的是按键任务，不能证明读研究、写作或使用 Agent 也会有同样效果。我由此提出一个待检验的设计猜想：隔一段时间给一个结构相近、表面不同的小任务，看看判断能否带走，而不是只让人反复确认同一种提醒。

例如，今天提醒你“这项研究只测了即时表现”，明天可以给一段同样有时间范围限制、但主题不同的摘要，让你自己圈出结论越界的地方。若每次都在同一句话旁给同一个红色标记，你很可能学会了看标记，没学会看证据。这里所谓“迁移”，就是换了材料还能用上原来的判断；这个解释不需要假装一项按键研究已经替我们验证了写作训练。能不能迁移，要在新材料里亲自检验。

Agent 也不必把所有中间步骤塞给人。它可以保存一张简短的记录：当时我选了什么、依据是什么、后来哪里被证明需要修改。下一次相似任务出现，再拿那处差异提醒我。这样的记录不是给工具夸耀“我记得你”，而是给人找回自己的判断轨迹；记录应只保留完成任务所需的信息，并由使用者决定是否继续保存。

## 最强的反对意见：我用工具就是为了省事

这个反对意见很有力。有人要在下班前完成文件，有人因为身体条件或注意力负担，本来就需要工具代做大量动作。把每个自动化过程变成测验，会把效率和可及性一同破坏。况且成年人完全有权决定今天只要结果；把“成长”强塞进每次操作，也是一种替人做主。

所以，我支持把打断设计成任务中的选择，而不是工具的道德姿态。用户可以说“只完成这件事”，也可以说“顺便教我辨别这一类问题”；同一个人今天赶工、明天练习，也应得到不同的响应。对于后果重、难以撤回的动作，需要事前确认，那是授权与风险控制；对于能帮助形成技能的短暂停顿，前提是人确实愿意学。这两种提醒的理由不能混在一起，免得所有提示都被误当成学习机会。

还有一个更难的问题：谁来判断什么值得学？Agent 可以检测重复出现的生词、经常被改掉的结论，或者同类错误再次发生，却不能替我决定某项能力对我的生活是否重要。它可以提出“你似乎总在这里修改结论，要不要练一次”，最终仍该由我选择。机器擅长发现模式，人的目标决定模式有没有价值；这也是我认为个人 Agent 再主动，也不该悄悄接管学习方向的原因。

这里还有个现实取舍。若一个人已经熟练掌握某项任务，还被反复要求解释基础步骤，提醒会变成低水平的干扰；若一个人连基础概念都没有，突然让他独立判断也不公平。合理的打断应该随能力变化：最初给例子和必要知识，中间留一点自己尝试的空间，熟练后减少提示，只在新变化或真实错误出现时再问。它不是永久开着的课堂。

## 用一周试试自己的打扰阈值

不需要等谁造出完美的个人 Agent，现在就可以用现有工具做一个小实验。选一件你经常交给 AI、又希望自己逐渐会做的事，例如读一段公开资料后判断结论有没有说过头。先写下你真正想学的判断：“我能识别一项结果只适用于什么样的对象、时间和任务。”若说不出要学什么，就先让工具完成工作，不必为了练习而练习。

接下来给工具一个很窄的约定：平常照常整理；碰到你指定的判断点，先不要给最终答案，只展示必要原文和两个可能的解释，让你先选并说出理由；随后再给来源位置和反例。一次只打断一个判断，别把整篇材料拆成考试。这个做法是我提出的试验方案，不是研究已经验证过的通用配方。

最后别只问“今天顺不顺”。隔一天找一份没有红色提示的新材料，自己做一次相同判断，再核对原文；若没有提升，就检查是提示太早、问题太难、反馈不清，还是这项能力根本不值得你投入。产品实验也有相似的提醒：[Steve Blank 在 2015 年谈最小可行产品时](https://steveblank.com/2015/05/06/build-measure-learn-throw-things-against-the-wall-and-see-if-they-work/)强调先写明要检验的假设，再设计能让自己学到东西的实验。“最小可行产品”在这里指为了检验一个具体猜测，拿给潜在使用者看的最简单的东西，不一定是一款做好的软件。那是一套创业方法，不是 AI 学习的实验证据；我借它提醒自己，别把“弹出了提醒”误当成“人学会了”。

回到开头那个生词。今天急着读完文章，释义一闪而过就很好；今天想积累词汇，停一下、猜一下、过后换个句子再认一次，才像真正的帮助。好的个人 Agent 应该能分辨这两个愿望，并允许人随时改口。我希望它替我省掉无意义的忙，也在我愿意变强的地方，留下一点刚好够用的停顿。
